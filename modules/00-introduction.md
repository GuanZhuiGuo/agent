## 0.1 从 Chatbot 到 Agent：一次真实的认知升级

2022 年，我们做 Chatbot，关心的是：
- Prompt 怎么写更好？
- 回答对不对？
- 用户体验顺不顺？

2024–2026，做 Agent，关心的多了一倍：
- 它**记得**上次说了什么吗？
- 它**查到**的信息是对的吗？
- 它**真的做了**那件事吗？还是只是"说"做了？
- 它**卡住**了会怎么办？
- 一次任务要花多少钱？要跑多久？
- 多个 Agent 要不要协作？谁听谁的？

> **一句话定义**
> **Chatbot 输出文字，Agent 输出行动。**
> Agent 是一个能在环境中**感知 – 思考 – 行动 – 记忆**的软件实体。

### 六大组件（PM 都要能说清楚）

| 组件 | 一句话解释 | PM 的典型问题 |
|---|---|---|
| **LLM Core** | Agent 的"大脑"，负责理解+生成 | 选哪个模型？多大尺寸？成本？ |
| **Memory 记忆** | 跨会话保持信息连续 | 记多久？记什么？谁能改？ |
| **Knowledge 知识库** | Agent 不知道的知识从哪来 | 哪些内容入库？更新频率？ |
| **Tools 工具** | 让 Agent 能**做事**而不是只**说话** | 给它哪些权限？谁来审批？ |
| **Planning 规划** | 把目标拆成有序动作 | 让它自由发挥，还是走固定流程？ |
| **Environment 环境** | Agent 感知并影响的世界 | 是文件系统？浏览器？IM？业务系统？ |

## 0.3 一个例子：把全景图"塞进"一个真实 Agent

**场景**：一个给运营同学用的"活动分析助手 Agent"。

| 组件 | 在这个 Agent 里长什么样 |
|---|---|
| LLM Core | GPT-4 class 或 Claude Sonnet class |
| Memory | 记住"用户习惯看哪些指标、关注哪个业务线" |
| Knowledge | 公司 Wiki + 历史活动复盘文档 + 指标口径文档 |
| Tools | SQL 查询工具 + BI 图表生成 + 发送到飞书 |
| Planning | 用户说"分析上周活动"→ 自动分解为 4 步 |
| Environment | 数据仓库 + BI 平台 + 飞书机器人 |

从"给运营写一个分析 Chatbot"升级到"给运营一个活动分析 Agent"，你会发现：
- 产品复杂度 × 3
- 工程工作量 × 5
- 但用户价值也 × 10

## 0.4 Agent 能力的光谱（重要）

别再用"是不是 Agent"这种二元问题提问。真实世界是一条光谱：

```
低自主                                                      高自主
─────────────────────────────────────────────────────────────▶
 Chat    Chat+RAG    工作流AI     工具调用Agent    规划Agent   自主Agent
   │         │           │             │              │          │
   │         │           │             │              │          │
 纯生成  知识增强    固定流程        单步行动        多步行动    长期目标
                                                              ＋自学习
```

**🧭 PM 决策点**：你的产品**真的需要**右边吗？

- 用户只是想要**答案** → 左边够
- 用户想要**答案 + 一点操作** → 中间（最高性价比区间！）
- 用户想要**托付一个完整任务** → 右边
- 用户想要**一直在后台帮我** → 更右

**⚠️ 最常见的产品错误**：
一上来就想做最右边（"给我做一个通用 Agent"），结果：
- 效果不稳定
- 成本爆炸
- 没人会为此付费

**更聪明的路径**：从光谱左边起步，随着数据 / 评估体系 / 用户信任累积，逐步右移。

## 0.5 本课不会教你什么

为了让你对课程范围心里有数：

❌ **不教**：
- 怎么训练 / 微调一个大模型
- 具体框架（LangChain / LangGraph / AutoGen / CrewAI）API 的用法
- 向量数据库的部署运维
- 特定编程语言的实现

✅ **教**：
- 什么样的产品适合做 Agent
- 每个组件的**产品决策树**
- 不同方案的**权衡（trade-off）**
- 评估、成本、风险的**度量方法**
- 给工程团队开**有信息量**的需求会

## 0.6 一张 PM 的"问题清单"（随身携带）

每次看到 / 评审一个 Agent 需求，问自己这 10 个问题：

1. 用户**到底**想要什么结果？（不是想要 Agent，是想要那个结果）
2. 这个任务**不用 Agent** 能做吗？
3. 失败了，代价多大？（可回滚 vs. 不可回滚）
4. 这个任务**有多少步**？
5. 中间需不需要**问用户**确认？
6. 它要**记住**跨会话的什么？
7. 它要**查询**什么外部知识？
8. 它需要调用**哪些工具**？权限谁批？
9. 怎么知道它**做对了**？
10. 一次任务**多少钱**？多久出结果？

**这 10 个问题** = 模块 01–08 的全部内容。

## 0.7 练习

1. 挑一个你熟悉的 AI 产品（Cursor、Coze、Manus、你自己做的也行），照 **0.2 全景图** 填一遍六个组件。
2. 在 **0.4 光谱** 上标出它目前处于哪里，并写一句"为什么不再往右"。
3. 用 **0.6 问题清单** 反问这个产品，至少挑出 3 个可优化点。
