# 模块 08 · 产品化、成本与落地

> 目标：把前面所有模块组合成一个"能赚钱 / 能规模化 / 能留存"的产品。

---

## 8.1 把技术能力翻译成产品价值

Agent 的技术能力光谱（模块 00）不等于产品价值。PM 的工作就是**做这层翻译**：

| 技术能力 | 用户感知的产品价值 |
|---|---|
| 记忆 | "它懂我"、"不用重复说" |
| RAG | "答案是对的"、"有出处" |
| 工具 | "它真的帮我做了事" |
| 规划 | "它能处理复杂的活" |
| 反思 | "它自己检查过了" |
| Multi-Agent | "像雇了个小团队" |

用户不会付费给"更好的模型"，只会付费给"更好的**结果**"。

---

## 8.2 Agent 产品的五种商业形态

| 形态 | 例子 | 计费逻辑 |
|---|---|---|
| Copilot 嵌入式 | Cursor、Notion AI、GitHub Copilot | 人头 / 订阅 |
| 对话式助手 | ChatGPT、Claude、Kimi | 免费+订阅+API |
| 垂直自动化 | 报销 / 简历筛选 / 合同审查 | 按任务 / 按席位 |
| 长任务托管 | Manus、Devin、Deep Research | 按任务 / 按订阅 |
| API 平台 | 给开发者的 Agent 构建平台（Coze/Dify） | 按调用量 / SaaS |

🧭 PM 决策：你的产品收入怎么来？决定了你要优化什么。

---

## 8.3 成本模型：PM 必须会估

一次任务的成本大致结构：

```
Task Cost ≈
    Σ(LLM 输入 token × $) + Σ(LLM 输出 token × $)
  + Σ(Embedding token × $)
  + Σ(工具调用费用)
  + 基础设施分摊（向量库/存储/带宽）
```

**一个实用的近似公式**（PM 估算用）：

```
单任务成本 ≈ 步数 × 平均每步 token × 模型单价
```

举例：
- 任务平均 8 步
- 每步 3K input + 0.5K output token
- 模型单价（Sonnet 级）：$3/Mtok in + $15/Mtok out
- 成本 ≈ 8 × (3K × $3 + 0.5K × $15) / 1M ≈ $0.13

🧭 PM 必须算：**单任务成本是否小于用户价值 / 定价？**

---

## 8.4 成本优化的九种手段

按"先做容易见效的"顺序：

1. **Prompt 瘦身**：去掉重复 instruction、压缩示例
2. **上下文瘦身**：裁剪无用历史、只传相关记忆
3. **RAG 精召回**：从召回 10 条减到 3 条（先 Rerank）
4. **缓存**：相同/相似 query 直接返回（Prompt / 语义缓存）
5. **模型分级（Routing）**：简单请求走小模型、复杂走大模型
6. **合并步骤**：能一次调用搞定的不要拆
7. **结构化输出**：强制 JSON，减少"解释冗余"
8. **Streaming**：降低感知延迟（不降本但提体验）
9. **长任务异步化**：让用户提交后走开，提升转化

---

## 8.5 延迟优化

用户能忍的延迟大致：

| 交互类型 | 可忍受延迟 |
|---|---|
| 对话首 token | < 2s |
| 完整回答 | < 10s |
| 复杂任务（带进度条） | 数分钟 |
| 明确的异步任务 | 数小时，通知即可 |

降延迟手段：
- **Streaming** 让用户尽快看到
- **并行**：可并行的工具/子 Agent 一起跑
- **预取**：用户还在说话时，就开始检索
- **小模型兜底**：一个更快的模型负责"先说一句等我想想"

---

## 8.6 UX 设计的 Agent 专属原则

PM 和设计合作时要守住这几条：

1. **透明**：展示思考 / 工具调用 / 引用来源
2. **可控**：随时中止、编辑、重试
3. **可追溯**：回看之前步骤、可分享
4. **可纠正**：用户能说"不是这个意思"并影响下一步
5. **不过度承诺**：先说清楚它不擅长什么
6. **善用"加载"**：让等待变信息（"正在查 3 个来源…"）
7. **明确告知错误**：出错要人话解释，不是堆技术日志

⚠️ 反模式：把 Agent 包装成"万能仆人"，结果一出错用户崩溃。**越强调自动化，错时落差越大。**

---

## 8.7 信任的阶梯

用户对 Agent 的信任不是一次建立的，是**阶梯式的**：

```
Step 1  读取：它只看我的东西
Step 2  建议：它给我建议，我决定
Step 3  执行（可撤销）：它做了，但我能撤
Step 4  执行（需确认）：它做前先问我
Step 5  执行（自主）：在某类场景下它直接做
Step 6  授权（长期）：一定金额/一定范围内任它处理
```

🧭 **PM 的产品路线图基本就是让用户沿这个阶梯往上走。**
- 过快跳级 → 用户不信任 → 流失
- 永远停在 Step 1 → 价值感太弱 → 竞争力弱

---

## 8.8 发布策略

Agent 产品建议用**渐进发布**：

1. 内部 dogfooding（先自己用）
2. Alpha（20 个真实用户）
3. Beta（受限白名单）
4. GA（全量）

每一阶段必须有：
- 评估集跑通
- Trace 可查
- Kill switch 就位
- 明确的反馈通道

---

## 8.9 运营：Agent 是"活"的产品

Chatbot 上线之后主要靠训练；Agent 上线之后，PM 要管**日常运营**：

- **知识库**：每周/每月更新（哪些文档过期了？）
- **记忆**：用户记忆的异常检测（某用户被 Agent 记了奇怪的东西）
- **工具**：新增 / 下线 / 失败率监控
- **Prompt**：定期审视（模型升级后以前的 prompt 可能不最优）
- **红队**：每季度跑一次
- **成本**：每月做一次成本结构复盘

📌 把运营动作**排进 Sprint**，否则会被淹没。

---

## 8.10 常见"落地死法"

| 死法 | 根因 | 对策 |
|---|---|---|
| demo 漂亮上线翻车 | 没评估集、没覆盖长尾 | 模块 07 |
| 月底被账单吓到 | 没成本上限、没分级 | 8.3–8.4 |
| 用户不信任 | 缺透明度/控制权 | 8.6–8.7 |
| 内部不采用 | 切入点太大、价值不聚焦 | 从一个狭窄场景起步 |
| 合规被叫停 | 记忆 / 数据 / 权限没治理 | 模块 02 / 07 |
| 做着做着没差异化 | 都是"接个模型+RAG" | 差异化=数据+工具+垂直流程 |

## 8.11 从 0 到 1 的 6 周示例路径

```
W1  选场景 / 写 PRD（模板在 templates/）
W2  建黄金集（20 条）+ 基线方案（工作流 + 单 Agent + RAG）
W3  工具清单 + HITL 关卡 + 栏杆
W4  评估 + trace + 红队第一轮
W5  Beta 白名单，收集真实 trace，迭代 Prompt / RAG
W6  修 top 3 问题，发布到更大范围；同时决定 "要不要做记忆/Multi-Agent"
```

**第 6 周的决定最关键**：有足够数据才能判断是否需要记忆 / Multi-Agent，而不是一开始就堆复杂度。

## 8.12 🛠 Agent PRD 交付物清单

一份合格的 Agent PRD 至少包含：

- [ ] 产品目标、用户故事、成功指标
- [ ] 能力光谱定位（模块 00）+ 规划模式（模块 05）

- [ ] RAG 设计（模块 03）
- [ ] 工具清单 + HITL 档位（模块 04）
- [ ] Multi-Agent 画布（若采用，模块 06）
- [ ] 栏杆（步数/成本/时间/红线）
- [ ] 评估方案：黄金集 / Rubric / 红队
- [ ] UX：透明度、控制权、失败文案
