# 模块 07 · 评估、可观测与安全

> 目标：学会"怎么证明 Agent 真的变好了"，建立可上线、可监控、可追责的工程闭环。

PM 不建立评估体系，就只能靠"我感觉它好了"这种原始办法说话。这个模块把你从"凭感觉"升级到"拿数据"。

---

## 7.1 评估的四个层次

```
┌──────────────────────────────────────────────────────────┐
│ L1  单元评估（Unit Eval）                                 │
│     针对单个能力/工具：能不能解析时间？能不能调对 API？   │
├──────────────────────────────────────────────────────────┤
│ L2  步骤评估（Step Eval）                                 │
│     每一步是否合理：选的工具对不对？参数对不对？          │
├──────────────────────────────────────────────────────────┤
│ L3  任务评估（Task Eval）                                 │
│     端到端：这个任务最终**做成了**吗？                    │
├──────────────────────────────────────────────────────────┤
│ L4  体验评估（UX Eval）                                   │
│     用户满意度、信任度、是否继续使用                      │
└──────────────────────────────────────────────────────────┘
```

对 PM 最有用的是 **L3 + L4**；但没有 L1/L2 做基础，上层数据会失焦。

---

## 7.2 评估的三种数据源

| 来源 | 成本 | 规模 | 质量 |
|---|---|---|---|
| 人工评估 | 高 | 小 | 高 |
| LLM-as-Judge | 低 | 大 | 中（要校准） |
| 用户行为信号 | ~0 | 最大 | 间接 |

**最佳实践**：三者混合。
- 小规模人工标注建立"黄金集"
- LLM-as-Judge 扩到大规模自动评
- 线上收集行为信号持续校准

---

## 7.3 PM 必建的三样东西

### 7.3.1 黄金评测集（Golden Set）

不做这个，别谈评估。

- 50–500 条**真实代表性任务**
- 每条包含：输入 / 期望输出 / 难度标签 / 类别标签
- 团队**共同维护**，每次发布前跑一遍

🧭 PM 负责：定义"期望输出长什么样"，**不是工程的事**。

### 7.3.2 评分标准（Rubric）

对主观任务（写作、分析），提前定义几条评分轴：

```
示例 Rubric（客服 Agent 回答）
  - 事实正确性     (1–5)
  - 回答完整性     (1–5)
  - 语气合适性     (1–5)
  - 是否给引用     (0/1)
  - 是否正确转人工 (0/1)
```

**PM 写 rubric = 定义产品质量。**

### 7.3.3 红队清单（Red Team）

专门设计用来"搞挂 Agent"的题目：

- 诱导越权（让它做它不该做的事）
- 诱导幻觉（问它不知道的事）
- 对抗注入（Prompt Injection）
- 边界值（超长输入、空输入、乱码）
- 多语言
- 敏感话题

上线前**必跑**。

## 7.4 LLM-as-Judge：用 AI 评 AI

让一个（通常更强或同强）LLM 按你给的 rubric 打分。

优点：
- 便宜、快、规模大
- 结果可追溯（有理由）

坑：
- **位置偏见**：更喜欢第一个/第二个选项
- **长度偏见**：更喜欢长答案
- **同源偏见**：自家模型评自家容易高分
- **口味偏见**：你没想到的莫名偏好

缓解：
- Prompt 里明确"不要因为长短/位置打分"
- 采用两两比较（pair-wise）而不是单条打分
- **用人工样本定期校准 Judge 本身**

---

## 7.5 可观测性（Observability）：Agent 的黑匣子

PM 要推动工程建立"**trace**"：

**一条 trace 应包含**：
- 用户原始输入
- 每一步（LLM 调用 / 工具调用）的输入、输出、耗时、成本
- 每步 LLM 的 prompt 全文（含 system、记忆、RAG context）
- 最终输出
- 用户反馈（👍👎 / 修改 / 放弃）

💡 没有 trace，任何 Agent 事故都是"灵异事件"。

工具：LangSmith / Langfuse / Arize / Weights & Biases / Helicone。PM 不用选型，但要在 PRD 里**明确要 trace**，这是基建级要求。

## 7.7 安全 & 合规红线

### 7.7.1 Prompt Injection（提示注入）
攻击者在输入/文档/网页里塞指令，让 Agent 违规。
- **防护**：分离 user input / system prompt / 工具结果的"信任等级"
- **原则**：永远不要信任工具返回内容里的指令

### 7.7.2 数据泄漏
Agent 把 A 用户的信息说给 B 用户。
- **防护**：严格的租户隔离 + 记忆/知识库按用户过滤

### 7.7.3 权限越权
Agent 调用了它不该调的工具。
- **防护**：工具级权限检查在 **Runtime** 层，不依赖 LLM 自觉

### 7.7.4 内容安全
不该生成的内容（违法、歧视、未成年不适宜）。
- **防护**：分类器 + 关键词 + 人审 + 日志

### 7.7.5 不可逆动作
发错邮件、改错库、错下订单。
- **防护**：HITL（C 档）+ 事后可撤销（见模块 04）

### 7.7.6 隐私与合规
GDPR / 个人信息保护法 / 数据出境……
- **防护**：PII 识别、脱敏、可删除、可导出、用户知情同意

## 7.8 上线前 Checklist（PM 自己要走一遍）

- [ ] 黄金集 ≥ 50 条，涵盖主要场景

- [ ] Trace 能查到每一步
- [ ] 核心指标看板已上线

## 7.9 持续改进闭环

```
        ┌─────────────────────────────────────────┐
        │                                          │
        ▼                                          │
    收集 trace                                     │
    + 用户反馈                                     │
        │                                          │
        ▼                                          │
    归因分析（哪一环错了）                          │
        │                                          │
        ▼                                          │
    改 Prompt / RAG / 工具描述 / 评估集            │
        │                                          │
        ▼                                          │
    评估集回跑，验证没退化                         │
        │                                          │
        ▼                                          │
    发布 → 线上监控 ────────────────────────────
```

🧭 PM 要主导这个闭环。没有这个闭环，Agent 产品**不是产品**，是一次性的玩具。

---

## 7.10 ⚠️ 常见反模式

1. **没有评估集，版本靠 demo 决策**
2. **只看满意度，忽略事实性/安全性**
3. **LLM-as-Judge 没校准，当真理用**
4. **没有 trace，线上事故找不到根因**
5. **只有好路径评估，没做红队**
6. **成本无上限，月底被账单吓到**

## 7.11 练习

1. 为你的产品建一个 **20 条** 的迷你黄金集（现在就开始）。
2. 为主要任务写一份 **Rubric**（3–5 条轴）。
3. 列 10 条 **红队题**（尽可能刁难）。
4. 打开一条真实 trace（或模拟一条），写一段"**事故复盘**"。
